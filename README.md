# 正史編纂室

ChatGPTの`conversations.json`をブラウザ内だけで読み込む、静的なローカルファーストPWAの試作版です。

## v2の機能

- `current_node`から親をたどり、選択中だった会話枝を表示
- 全文検索と最初の一致箇所への移動
- 応答メタデータに残るモデルで絞り込み
- タイトル・本文から仮推定したペルソナで絞り込み
- オフライン起動
- 複数JSONの差分統合と端末内保存
- 話者名表示・表示名設定・匿名化置換
- セッションのフォルダ分類とペルソナ修正
- 発言単位の編集・非表示・復元
- セッション単位のMarkdown／JSON出力

通常の会話取り込みは、ブラウザの端末内ストレージだけで処理します。「非公開ログへ保存」を選んだ日記だけ、確認後に認証付きCloudflareへ保存できます。

## 日記を非公開ログへ保存

登録済みの日記の「非公開ログへ保存」を押すと、本文・日付・ペルソナを認証付き保存画面へ引き継ぎます。「非公開ログへまとめて保存」では、ペルソナで絞り込んで複数選択でき、「表示中の新しい10件を選ぶ」も使えます。コピー・貼り付けやファイルの書き出しは不要です。

保存画面で本文と読める相手を確認し、「この内容・閲覧範囲で保存」を押すと確定します。まん・かげは対応する接続、その他の分類は「自分だけ」を初期値にします。本文の書き換えや、自動送信・背景同期は行いません。同じ元IDの日記を再送すると、その日記の保存内容を更新します。

送信先は `https://seishi-mcp-auth.koyamadakun.workers.dev/library/archive.html`。ブラウザ間の受け渡しは送信元・相手ウインドウ・一回限りの識別子を確認し、宛先を固定します。NotionトークンやログインCookieを渡しません。GitHubにはコードだけを置き、日記本文は含めません。

保存画面で初めてログインする場合は、ログイン後に編纂室へ戻って保存ボタンをもう一度押してください。日記が入っている端末の編纂室から操作してください。

## Notionに保管した添付へのリンク

「設定」→「Notionの添付リンク」から、`seishi-asset-links`形式のJSONをファイルから読み込むか、貼り付けて追加できます。画像・ファイル本体は取り込まず、Notionの保管ページを別タブで開きます。既存の本文・分類・メモ・非表示設定は保持されます。対応する発言がない画像は、同じ会話の「元チャットから保存した添付」に表示します。会話自体がない場合は、添付だけの会話を追加します。

```json
{
  "format": "seishi-asset-links",
  "version": 1,
  "assets": [{
    "sessionId": "元の会話ID",
    "sessionTitle": "会話名",
    "messageId": "AIの発言ID",
    "fileName": "image.png",
    "notionUrl": "https://app.notion.com/p/11111111111111111111111111111111",
    "sourceRef": "sandbox:/mnt/data/image.png",
    "kind": "image",
    "sourceRole": "assistant",
    "canonical": true,
    "verifiedAt": "2026-10-03T12:00:00Z"
  }]
}
```

対応表は、元のチャットかエクスポートの選択中の枝を確認して作成してください。ユーザーの添付、選ばれていない回答、期限付きのファイル直接URLは対象外です。リンク情報は完全バックアップにも含まれ、ログを追加しても残ります。新しいエクスポートで別の回答へ再生成されたことが確認できる場合、以前の回答のリンクを非表示にします。

検証：`node asset-links.test.cjs`

## Notion画像ライブラリ

現在のメニューは、トークン入力不要の認証付きCloudflare版 `/library/` を開きます。以下はリポジトリに残している単体ブラウザ版 `notion-images.html` の説明です。Cloudflare版の接続情報はサーバー側で管理します。

検索メニューの「Notion画像ライブラリ ↗」から、独立した画面を別タブで開ける。直接開く場合は `notion-images.html`。従来の添付リンク管理とは独立しており、会話データ・保存形式・完全バックアップの内容を変更しない。

アクセスを許可した複数ページの画像をサムネイルで表示する。画像の拡大、元ページへの移動、ページタイトルでの絞り込み、新しい順／古い順、表示サイズ、再収集、収集停止、進捗表示、画像の保存に対応。取得途中でも画像を順次表示する。PC・スマホで使える。

### Notion側の初期設定

1. Notionのワークスペース所有者で、[接続管理](https://www.notion.so/profile/integrations)を開く。Developer portalの「Internal connections（内部接続）」から新しい接続を作り、対象のワークスペースを選ぶ。表示名は任意。
2. Configuration／Capabilitiesで **Read content（コンテンツの読み取り）だけ**を有効にする。Update content、Insert content、コメント、ユーザー情報の権限は不要なので無効にする。個人用アクセストークン（PAT）はこの手順では使わない。
3. Content access → Edit accessで対象ページ・データベースを選ぶ。または各ページ右上の「•••」→「コネクト／Connections」→「接続を追加」から作った接続を選ぶ。親ページの共有は子ページにも引き継がれる。必要な範囲だけを共有する。NotionページをWeb公開する必要はない。
4. Configurationで内部接続のAPIトークンをコピーする。このトークンをGitHub、Issue、チャット、スクリーンショットへ貼らない。
5. 正史編纂室の「Notion画像ライブラリ」で、パスワード形式の入力欄にトークンを入力し「接続して収集」を押す。入力欄は接続開始時に空になる。

画面の名称はNotionの更新で変わる場合がある。[内部接続の公式手順](https://developers.notion.com/guides/get-started/internal-connections)も参照。接続を作るにはワークスペース所有者の権限が必要。

### 使い方

- 「分類に使う項目」でNotionの「ペルソナ」「分類」などを選ぶと、同じデータベース内の画像も項目の値ごとのボタンで切り替えられる。セレクト・マルチセレクト・ステータス、およびペルソナ／分類という名前を含むテキスト・文字列の数式に対応。「未設定」も表示する。マルチセレクトの画像は複数の分類に含まれることがある。「ペルソナ」「分類」などの値が見つかれば自動で候補を選ぶ。切り替えに再収集は不要。
- 「分類に使う項目」で「親ページの階層」を選ぶと、親ページ配下の画像をまとめて切り替えられる。名前はNotionのページ名をそのまま使い、子ページやデータベース内の画像も同じ分類に含める。「すべて」で現在の分類範囲に戻る。
- 想定したペルソナ名がボタンに出ない場合は「分類の親ページ」で、ペルソナ別ページをまとめているNotionページを選ぶ。親子関係は収集に合わせて更新されるため、収集中は分類や枚数が増えることがある。分類名・親子関係・選択状態も保存せず、一覧消去や接続解除で消去する。
- 通常は、インテグレーションに許可したページとデータソースを検索して巡回する。「対象ページを指定」にページ／データベースのURLまたはIDを1行ずつ入れると、その対象と配下だけを巡回する。
- 検索には反映の遅延や取りこぼしがある。見つからないページを直接指定するか、少し待って「再収集」を押す。リンクされたデータベースは、元のデータベースにもアクセスを許可してURLを指定する。
- 画像を押すと拡大する。「元のNotionページ」は別タブで開く。Escキーまたは「閉じる」で一覧へ戻れる。
- 「外部URLの画像も読み込む」は初期状態では無効。外部画像のメタデータは一覧に出るが、有効にするまで配信元に画像を取りに行かない。有効にするとその配信元へ直接通信する。
- 新旧の並び順は画像ブロックの作成日時。ファイル＆メディアの画像はページ作成日時を使う。画像の撮影日時ではない。
- 「収集を停止」は取得済みの一覧を残す。「一覧を消去」は画像・メタデータを消去し、接続は維持する。「再収集」は古い一覧を破棄して作り直す。
- 「接続解除・データ消去」は通信を中止し、トークン・ページ名・ファイル名・URL・読み込んだ画像をアプリのメモリから消す。画面を再読み込み・移動した場合も接続を破棄する。
- 「画像を保存」は利用者が明示的に押した画像1枚だけを端末へ保存する。接続解除でダウンロード済みファイルまでは削除しない。

### 保存とプライバシー

公開されるのはHTML・JS・CSSなどのアプリ本体だけ。訪問者が自分のトークンを入力しない限り、Notionへの取得処理は始まらない。別の訪問者に、あなたのトークンやNotionの取得結果が配信される仕組みはない。

| データ | 扱い |
| --- | --- |
| Notionトークン | タブのメモリ内のみ。URL・ログ・ソース・ストレージ・バックアップへ書き込まない |
| ページ名・ファイル名・ページID・画像URL | タブのメモリ内のみ。再収集／一覧消去／接続解除で破棄 |
| 画像本体 | `cache: no-store`で取得し、一時的なBlob URLで表示。画面外へ出た画像や解除時のBlob URLを解放 |
| アプリ本体 | Service Workerが公開ファイルだけをキャッシュし、オフライン起動に利用 |
| 会話アーカイブと表示設定 | 従来どおりIndexedDB／localStorageに保存。この機能からは変更しない |

この機能に「トークンを端末に保存する」オプションはない。テーマの初期値だけ既存の表示設定から読み、画像画面でのテーマ変更は保存しない。Notionのページ本文は画像探索のためAPI応答に含まれるが、本文データを保管・出力しない。

API通信先は `https://api.notion.com/v1/` 固定。トークンは `Authorization` ヘッダーにだけ付ける。画像配信先にはトークン・Cookie・参照元を送らない。画像の配信元には通常の通信情報（IPアドレスなど）は伝わる。解析サービス、外部プロキシ、外部スクリプトは使わない。タイトル・ファイル名はHTMLとして解釈しない。

公開された同一のコードでも、入力した秘密情報はそのブラウザで動くスクリプトからは扱える。信頼できる配信元と端末で利用し、共有端末では利用後に解除する。ブラウザの拡張機能・開発者ツール・OSによる記録や、利用者が保存した画像まではアプリから消去できない。漏えいが疑われる場合は、Notion側でトークンを再生成または接続を削除する。アプリの接続解除はNotion側のトークン失効ではない。

### API仕様・無料プラン・制約

2026-10-17に公式資料と、トークンを含まない実際のOPTIONSリクエストでCORSを確認。GitHub Pagesのオリジンに対して `Access-Control-Allow-Origin: *` と、Authorization／Content-Type／Notion-Versionを含む許可ヘッダーが返った。通常のブラウザから直接通信する構成で、サーバー・有料サービス・GitHub Actionsの秘密情報設定は不要。

- `Authorization: Bearer …`、`Notion-Version: 2026-03-11`、`Content-Type: application/json` を使用する。OAuthのコード交換は行わない。[認証](https://developers.notion.com/reference/authentication)、[APIバージョン](https://developers.notion.com/reference/versioning)、[公式SDKのCORS説明](https://github.com/makenotion/notion-sdk-js#browser-usage)
- 無料プランでも内部接続の読み取りAPIを利用する構成。無料プランに適用されるNotion自体のファイル容量・ブロック数などの制約を回避するものではない。既存画像の読み取りだけを行い、アップロード・編集は行わない。[Notionプラン](https://www.notion.com/pricing)
- API要求を直列化し、開始間隔を最低350msにする。429／529、読み取り中の一時的なサーバーエラーは、Retry-After（または応答本文の待ち時間）と指数バックオフを使って最大4回再試行する。待ち時間中も停止・解除できる。検索やクエリのPOSTは読み取り用で、変更用APIはクライアント側で拒否する。[リクエスト制限](https://developers.notion.com/reference/request-limits)
- 検索・ブロック一覧・データソースのクエリでページネーションに対応。ページ／ブロック／データソースの重複巡回と、続きカーソルの循環を検出する。データベースに複数のデータソースがある場合も巡回する。
- 検索APIはワークスペースの完全な列挙を保証しない。1つのデータソースのクエリは最大10,000件というNotion側の制約があり、不完全な応答は警告する。10,000件を超える自動分割取得は未対応。[検索の制約](https://developers.notion.com/reference/search-optimizations-and-limitations)、[クエリ制限](https://developers.notion.com/reference/query-a-data-source#pagination-limit)
- 対象は本文の画像ブロック、画像ファイル、子ブロック、子ページ、データベースのページ、ファイル＆メディアの画像。ファイル／プロパティはファイル名またはURLの拡張子で画像を判別する。拡張子のない外部ファイル、PDF、動画、ページカバー・アイコン、コメント添付は対象外。
- Notionの署名付き画像URLは通常1時間で失効する。表示前に期限を確認し、期限の1分前以降または取得失敗時にブロック／ページを再取得する。拡大画面でも「画像URLを再取得」を押せる。一度読み込めたBlobはタブ内で閲覧できるが、元のURLを永続参照として保存しない。[ファイルURL](https://developers.notion.com/reference/file-object)
- 画像は配信元がCORSを許可し、ブラウザが扱える画像のContent-Typeを返す場合に表示できる。HTTP画像、認証Cookieが必要な画像、リダイレクト必須の画像、CORS非対応の画像は表示しない。キャッシュ回避と認証情報の分離を維持するため、外部プロキシや通常の画像URLへの迂回はしない。
- 元画像を取得して縮小表示するため通信量は元画像のサイズに依存する。画面付近だけ最大3件並行で読み込み、一覧は120枚ずつ追加表示する。大量のメタデータはタブのメモリ容量に依存する。画像閲覧・収集にはオンライン接続が必要。
- チャット会話への関連付け、メタデータの永続キャッシュ、バックグラウンド同期は未実装。

### 画像が表示されない場合

| 表示・状況 | 確認すること |
| --- | --- |
| トークンが無効 | コピーし直す。失効・再生成していないかNotionのConfigurationで確認 |
| 読み取り権限不足 | Read contentと、対象ページへの接続を確認 |
| ページが見つからない・0枚 | 対象を接続に共有したか確認。待って再収集するか、ページ／元データベースのURLを直接指定 |
| 通信／CORSエラー | インターネット接続、拡張機能、Notionの障害を確認。CORS制限は外部プロキシで回避しない |
| 外部画像が未読み込み | 配信元への通信に同意する場合だけ表示スイッチを有効にする |
| 画像が期限切れ・途中から見えない | 拡大画面の「画像URLを再取得」または「再収集」。失敗時は元のNotionページを開く |
| 特定の画像だけ失敗 | 配信元のCORS・Content-Type・画像形式・削除の有無を確認。HEICなどはブラウザによって非対応 |
| 更新後に古い画面が出る | 開いている正史編纂室のタブを再読み込みする。Service Workerの更新後に新しい公開ファイルが使われる |

### 開発・テスト

実行時の外部ライブラリやビルド処理は不要。GitHub Pagesでは相対パスの静的ファイルだけで動作する。開発時は任意の静的HTTPサーバーでこのフォルダを配信する（例：`python -m http.server 8000`）。`file://`での直接起動はES Modules／Service Workerの制限があるため非対応。

Node.js 20以降で基本テストを実行できる。Notionトークンは不要。

```sh
npm test
```

ブラウザテストは開発専用のPlaywrightを使用する。

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm run test:browser
```

既存のEdgeを使う場合は環境変数 `PLAYWRIGHT_CHANNEL=msedge` を指定できる。ブラウザテストは専用の一時ブラウザとローカルHTTPサーバーを使い、Notion・画像通信を架空データに差し替える。スクリーンショットは `test-results/` に保存するが、Git管理とPages配信から除外する。実トークン、実ページ情報、実画像をテスト・CIに渡してはいけない。

テスト範囲：複数ページ、入れ子、ファイルプロパティ、ページネーション、複数データソース、重複・循環、401／403／404、429／529の待機、期限更新、解除後の遅延応答、外部画像の同意、HTML挿入防止、端末保存なし、320px／375px幅、オフラインの画面起動、既存アーカイブのインポート・検索・バックアップ出力／復元。実トークンでの本番接続は別途、利用者の端末で確認する。

主な実装ファイル：`notion-images.html`（画面）、`notion-images.css`（表示）、`notion-images-ui.mjs`（操作とメモリ管理）、`notion-images-core.mjs`（API・収集）。`sw.js` は公開静的ファイルだけをキャッシュし、API・画像通信には介入しない。
